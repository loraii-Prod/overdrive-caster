# 4K scene validation

Every broadcast scene rendered at 3840×2160 (headless Chrome, software raster, frozen frame, seeded show).
Generated by `e2e-rig/4k/scene_audit.py`. **Not real OBS**: GPU behaviour is pending the production-PC test (`docs/4K-PERF-TEST.md`).

- **Native** = 4K frame vs Chrome rasterising the same frame natively at 2× (99 dB = identical pixels).
- **Layout** = 4K frame scaled to 1080 vs the 1080 render (≥ 30 dB = nothing moved; differences are anti-aliasing).
- **Cut text** = text clipped by its box, at 4K / at 1080 (must match).
- **Upscaled** = images or video drawn larger than their own pixels at 4K (see `docs/4K-ASSET-REPORT.md`).

Result: **30/30 scenes pass**. No scene needed a code change for 4K: layouts are identical, the same text is cut at both resolutions (the existing ellipsis on long names and role chips, unchanged), and every vector and text element is drawn at native 4K. What limits 4K picture quality is the raster files listed in the last column.

Notes:
- `/output/ticker` is empty by design in the default event: its brand skin draws the ticker inside the skin's own bar (`show.brand.skin`). The standalone ticker appears for events without a skin.
- `/output/trio` shows two tiles because the fixture puts two casters in the booth. Trio framing is covered by the camera-sync suite.
- 4K stills of every scene: `docs/4k/scenes-4k-contact-sheet.jpg` (overview), full-resolution PNGs from `scene_audit.py` in `/tmp/4k/scenes/`.
- Reproduce: `e2e-rig/4k/fixture.sh && OD_STATE=/tmp/od4k/state.json python3 e2e-rig/4k/scene_audit.py --doc`.
